# W3-D4 ｜ 引用溯源：让每个答案都能「点到原文」

> **前置**：`search()` 已可用。
> **今日一句话**：无引用的 RAG 是玄学，有引用的 RAG 是工具——引用是用户信任的唯一来源，也是幻觉的照妖镜。

## 今日验收

- [ ] `src/answer.ts`：`answer(question)` = 检索 top-5 → 构建带编号的上下文 → 生成带 `[1][2]` 引用标记的答案
- [ ] 每个答案末尾附「来源」清单：编号 + source + heading + 原文片段（前 80 字）
- [ ] 引用完整性校验：答案中出现的每个 `[n]` 都存在于来源清单，出现未定义编号时重试（复用作品 1 的自修复模式）
- [ ] 拒答生效：检索分数全部低于阈值时，输出「资料中未找到相关内容」而不是硬答

## 任务卡

### T1 · 带编号的上下文构建（10min）

```ts
function buildContext(chunks: Chunk[]): string {
  return chunks
    .map((c, i) => `[${i + 1}] （来源：${c.source} · ${c.heading}）\n${c.content}`)
    .join('\n\n')
}

const system = [
  '你是一个资料问答助手，只能依据 <资料> 中的内容回答问题。',
  '引用资料时必须在句末标注来源编号，如 [1] 或 [2][3]。',
  '资料不足以回答时，回答「资料中未找到相关内容」，禁止编造。',
  '不要输出资料之外的知识，即使你知道答案。',
].join('\n')
```

**决策点**：编号 `[n]` 而不是让模型复述文件名——编号短、错不了、可程序校验；复述文件名会有大小写/截断等无穷变体。**让模型输出「可枚举的短符号」，校验交给代码**。

### T2 · 引用校验与自修复（15min）

```ts
const cited = new Set([...answer.matchAll(/\[(\d+)\]/g)].map(m => Number(m[1])))
const invalid = [...cited].filter(n => n < 1 || n > chunks.length)
if (invalid.length) {
  // 把非法编号反馈给模型重试一次（复用 W1-D2 的 generateWithRetry 思路）
}
```

**原理**：模型会偶尔「编造编号」或张冠李戴（内容是 A 来源却标 B）——校验能抓住前者的编号合法性，抓不住后者的语义错配（那是评测的活，明天见）。**校验管格式，评测管语义**，分工要清楚。

### T3 · 来源清单与定位（10min）

### T4 · 拒答阈值（10min）

```ts
const MIN_SCORE = 0.45  // 初始值，明天评测校准
const valid = chunks.filter(c => c.score >= MIN_SCORE)
if (!valid.length) return { answer: '资料中未找到相关内容。', sources: [] }
```

**决策点**：阈值不是拍脑袋的终值——今天先给 0.45 让系统「能拒答」，明天用评测集看「该拒的拒了没、不该拒的误伤了没」再校准。**先让机制存在，再让数值变准**。

## 关键决策与原理

1. **引用是 RAG 的信任协议**：用户核对一个引用的成本远低于验证整篇答案；企业场景（HR/法务/医疗）无引用的 RAG 根本过不了验收——这也是面试聊 RAG 必谈的一点；
2. **格式靠校验、语义靠评测**：运行时的代码防线（编号合法性）与离线的评测防线（引用是否张冠李戴）是两道独立的闸，别指望一道管全部；
3. **拒答是功能不是失败**：「不知道就说不知道」是 RAG 区别于裸 LLM 的核心价值；拒答阈值定太高会误伤（都拒答），定太低形同虚设——它是需要评测校准的产品参数；
4. **system 三句模板**（只能依据资料 / 必须标引用 / 不足则拒答）是所有资料问答类功能的通用起点，值得存成 snippet。

## 自测题（答完翻底部）

1. 为什么让模型输出 `[n]` 编号而不是复述来源文件名？
2. 引用校验能抓住什么、抓不住什么？抓不住的交给谁？
3. 拒答阈值今天为什么可以先拍脑袋 0.45？
4. 「拒答是功能不是失败」在产品上意味着什么？
5. 给资料问答写 system 的「三句模板」是哪三句？

---

## 答案与解析

1. 编号是短小、可枚举、可程序化校验的符号；文件名是自由文本，会有变体和截断，校验成本高且不可靠——「模型出符号，代码做校验」是可靠分工；
2. 抓得住编号合法性（是否存在、是否越界）；抓不住语义错配（引用指向错误来源）。语义层面交给评测集（golden set）离线把关；
3. 因为机制先于数值：先让「拒答能力」存在并跑通全链路，明天评测集会给出误拒/漏拒数据来校准——工程上「能调整」比「一开始就对」重要；
4. 意味着拒答是精心设计的产品行为（有话术、有引导下一步），而不是系统的报错；用户对「坦承不知道」的系统的信任反而高于一本正经胡说的系统；
5. 只能依据资料回答；引用必须标注编号；资料不足时明确拒答不编造。
