## 概念讲解

**为什么是这三件套？** 一个类比：

- **Node**（运行时）= 发动机：你的 AI 应用代码最终靠它跑起来；
- **pnpm**（包管理器）= 加油站：一键安装别人写好的库（比如下周要用的 AI SDK）；
- **Git**（版本控制）= 行车记录仪：每一次改动都有存档，随时回滚。

前端转 AI 应用开发，**环境门槛几乎为零**——你缺的不是工具，是用这些工具做后端逻辑的经验。本周就是把这个地基打牢。

**版本要求**：AI 生态普遍要求 Node ≥ 20（部分新特性需要 22）。Windows 上推荐用 **fnm** 或 **nvm-windows** 管理版本，方便随时切换。

## 自测题（先答，再翻到底部对答案）

1. Node、pnpm、Git 分别对应类比里的什么？各自解决什么问题？
2. 为什么 AI 应用开发生态普遍要求 Node ≥ 20？
3. pnpm 和 npm 最核心的区别是什么（一句话）？
4. `git config --global user.email` 配置的邮箱会在什么时候被用到？
5. `pnpm init` 做了什么、生成了什么文件？

---

## 答案与解析

1. Node=发动机（运行代码），pnpm=加油站（装依赖），Git=行车记录仪（版本存档/回滚）。
2. 新版语言特性（如原生跑 TS 的趋势）、主流库的最低支持线都卡在 18/20 以上；版本太新反而可能有兼容坑，20/22 LTS 最稳。
3. pnpm 用全局硬链接存储共享依赖，装得快、磁盘占用小、天然避免「幽灵依赖」（没声明的包也能被引用的问题）。
4. 每一次 `git commit` 的作者信息里都会写入这个邮箱——GitHub 上也是靠它把提交关联到你的账号（你已用 litao / 964374951@qq.com，与 GitHub 账号绑定一致即可）。
5. 在当前目录初始化一个 Node 项目，生成 `package.json`——它相当于项目的「身份证」：记录项目名、依赖清单、可执行脚本。
