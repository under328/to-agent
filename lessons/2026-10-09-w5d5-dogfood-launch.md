## 任务卡

### T1 · 部署决策：与演示型应用反着来（20min，今天的方法论核心）

对比两类应用的部署诉求：

| | 演示型（作品1/docqa） | 私有写入型（ai-notes） |
| --- | --- | --- |
| 数据 | 只读演示库，公开无妨 | **私有且持续增长**，绝不上公网裸奔 |
| 写路径 | 可缺席（W4-D5 只读库） | 是产品本体 |
| 可用性要求 | 访客随手看 | 你自己每天要用，挂了会暴怒 |
| 成本敏感度 | 免费额度够 | 自己掏钱，能省则省 |

**决策：v1 = 本地常驻 + 局域网访问**。理由：①隐私零风险（数据不出本机）；②写路径天然完整（本地 SQLite 就是最佳形态）；③成本为零；④手机在 WiFi 下访问 `http://<局域网IP>:3000` 即可随时随地录入——覆盖 90% 的使用场景。

**写路径上云的真实成本**（为什么现在不做）：需要持久卷或云库（Turso）、需要鉴权（公网服务裸奔等于笔记公开）、需要 HTTPS（密码学复杂度）——每一条都是真实工程投入，而当前没有一条被真实需求触发。**记录为演进路线，需求触发再动**（与 W4-D5 同款决策框架，你已经第二次用它了）。

### T2 · 常驻与局域网（15min）

```bash
# pm2 常驻（或 Windows 任务计划程序开机自启）
pnpm add -g pm2
pm2 start "pnpm start" --name ai-notes
pm2 startup   # 开机自启

# 手机访问：node 启动时监听 0.0.0.0，防火墙放行 3000 端口
# Windows 防火墙：netsh advfirewall firewall add rule name="ai-notes" dir=in action=allow protocol=TCP localport=3000
```

### T3 · 备份与恢复演练（15min，自用产品的生命线）

```bash
# scripts/backup.ps1：每日任务计划执行
Copy-Item ai-notes.db "D:\backup\ai-notes-$(Get-Date -Format yyyyMMdd).db"
Copy-Item ai-notes.db "$env:ONEDRIVE\backup\ai-notes-$(Get-Date -Format yyyyMMdd).db"
```

**恢复演练是备份的一半价值**：拿昨天的备份文件在一个空目录「装回」应用跑通——没验证过恢复的备份等于没有备份。简化版 3-2-1 原则：两份副本（本地 + 网盘）、一种异地。

## 关键决策与原理

1. **部署形态跟随数据性质**：演示型产品可以「只读库上公网」，私有写入型产品的默认形态是「数据在本地、访问在可信网络」——先分清产品属于哪类，部署方案自然浮现；
2. **「需求触发的演进」第二次上场**：云部署的全部前置条件（鉴权/HTTPS/云库）都写进演进路线但不做——与 W4-D5、W5-D1 的 tags 迁移条件一脉相承，这套「现在不做 + 何时做」的写法就是你个人的架构决策记录（ADR）风格；
3. **备份的完整性 = 备份 + 演练**：数据不可再生的自用产品里，备份优先级高于任何新功能；
4. **狗粮是独立开发的免费用户研究**：7 天使用日志积累的摩擦清单，比任何想象中的 roadmap 都可靠——W6 开工前的第一件事就是读它。

## 自测题（答完翻底部）

1. 私有写入型与演示型应用在部署诉求上的四个差异？
2. 为什么「写路径上云」现在不做？触发信号是什么？
3. 恢复演练为什么是备份的一半价值？
4. 局域网方案覆盖不了的场景是什么？那正是演进路线的什么信号？
5. 狗粮日志要记录的四个字段为什么是这几个？

---

## 答案与解析

1. 数据私有性（不可公开 vs 可公开）、写路径（本体 vs 可缺席）、可用性要求（日用暴怒线 vs 随手看）、成本归属（自己掏 vs 免费额度）；
2. 上云的前置投入（鉴权/HTTPS/云库）没有被真实需求触发；信号=「出门在外需要录入/查阅」的频率高到局域网方案开始漏需求——需求驱动，不是技术驱动；
3. 备份只证明「存了」，演练才证明「能回来」；未经验证的备份在真实事故时可能因格式/依赖问题失效——恢复路径可用性才是备份的目的地；
4. 离开家庭/办公室 WiFi 时的录入与查阅；这正是「云部署」演进路线的需求信号——记录频率，够了就启动；
5. 录入量（用量真实度）、卡点（摩擦清单）、整理质量（AI 功能真实水平）、想要什么（需求池）——分别对应 W6 开发的验证、优先级、质量基线与 backlog。
