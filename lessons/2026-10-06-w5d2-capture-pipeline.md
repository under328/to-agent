# W5-D2 ｜ 录入管道：粘贴入口与 Bookmarklet 剪藏

> **前置**：D1 的产品定义与脚手架就绪。
> **今日一句话**：录入摩擦每低一分，狗粮周的真实使用量就高一截——今天是「产品生死线」的一天。

## 今日验收

- [ ] 首页极速录入：单个大输入框，粘贴即存（Ctrl+Enter 提交，全程 ≤3 秒）
- [ ] Bookmarklet 剪藏：任意网页一键把「标题 + URL + 选中文本」送进录入页（预填完成）
- [ ] 去重：同 URL+选中文本的 hash 重复入库时提示已存在（幂等）
- [ ] 空内容/超长内容（>2 万字符）在入口处拦截并给出人话提示

## 任务卡

### T1 · 极速录入页（15min）

设计约束：**单输入框、无表单、无必填校验**——title 可选（缺省取首行或前 20 字），粘贴完 Ctrl+Enter 直接 POST。录入成功的反馈是「输入框清空 + 右下角 toast」，**不打断下一次录入**——批量录入场景（开完会倒 10 条笔记）是真实高频路径。

### T2 · Bookmarklet（20min，今天的主角）

```js
javascript:(() => {
  const t = encodeURIComponent(document.title);
  const u = encodeURIComponent(location.href);
  const s = encodeURIComponent(String(getSelection() || ''));
  window.open(`http://localhost:3000/clip?title=${t}&url=${u}&text=${s}`, '_blank');
})();
```

存成浏览器书签（URL 栏直接粘这段 JS），在任意网页点它 → 录入页以预填状态打开 → 确认入库。

**决策点（为什么不做浏览器扩展）**：扩展要处理 manifest/签名/上架/跨浏览器兼容，起步成本数天；bookmarklet 是一行 JS，五分钟能用。**剪藏的核心诉求是「把内容送到录入页」**，GET 预填完全够——先验证「你会不会真的用」，再谈工程化。代价如实记录：无法抓页面正文（只有选区）、依赖本地服务在线。

**细节坑**：`/clip` 页从 URL query 读参预填；选中文本可能为空（只剪标题+链接也是有效笔记，不要拦）。

### T3 · 去重与幂等（15min）

```ts
const dup = createHash('sha256').update(`${url}|${text}`).digest('hex').slice(0, 16)
// notes 表加 dup_key 列 + 唯一索引；INSERT 前查询，命中则返回已有 id + toast「已存在」
```

**决策点**：去重键为什么是 `url|text` 而不是单独 url——同一篇文章你会剪多次不同段落，全 url 去重会误伤「分段剪藏」的真实行为。**去重规则要跟着使用意图走**，不是越严越好。

### T4 · 入口防御（10min）

空内容、>2 万字符（embedding 成本与切块质量双重红线）、纯空白字符——在 API 入口统一拦截，错误信息说人话（「内容太长啦，先拆成两条吧」）。入口校验的意义：**脏数据一旦入库，污染的是之后的每一次检索与整理**。

## 关键决策与原理

1. **录入摩擦是这类产品的第一性指标**：从「看到信息」到「存好了」每多一步，真实使用率断崖式下降——所有设计围绕「3 秒」这个数字展开；
2. **bookmarklet 先行的验证哲学**：用最土的方案验证「剪藏」这个动作的真实使用频率，数据好再投资扩展——**工具的工程等级应该跟着验证程度走**；
3. **去重是产品行为不是技术洁癖**：误伤分段剪藏的去重规则会让用户（你）放弃剪藏——规则设计的输入是使用意图；
4. **入口是数据质量的总闸门**：RAG 的上限由入库数据质量决定（W3 已验证过），录入端多拦一道，下游整理/检索/评测全部受益。

## 进阶挑战（选做）

- 「剪藏命中已有笔记」时提供「追加到该笔记」选项（合并而非丢弃）；
- 录入页支持简单的 TODO 语法速记（`- [ ]` 开头的行自动归类为 action 项）。

## 自测题（答完翻底部）

1. 「3 秒录入」这个指标为什么是第一性的？
2. bookmarklet 相比浏览器扩展的取舍是什么？什么时候值得升级？
3. 去重键为什么是 `url|text` 组合？
4. 入口拦截超长内容的双重理由？
5. 批量录入场景对 UI 反馈设计提出了什么要求？

---

## 答案与解析

1. 录入摩擦直接决定真实使用率：摩擦是每次使用的固定税，日积月累决定产品「活得下去」还是「变成三分钟热度」；
2. bookmarklet 零上架成本、五分钟可用，适合验证使用频率；当「剪藏频率高 + 需要正文全文/截图」时再投资扩展（数天成本换来更强能力）；
3. 同一文章分段剪藏是合法使用意图（每段是独立知识单元），只按 url 去重会误伤；组合键精确表达「同一段内容不重复存」；
4. embedding 成本随长度线性涨 + 超长文本切块质量恶化（W3-D2 的语义稀释结论）——既省钱又保质量；
5. 批量录入时不能每次都弹窗打断（会翻倍操作成本），反馈要「边缘化」：toast、清空输入框、保持焦点，让用户进入连续录入流。
